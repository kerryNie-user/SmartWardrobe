# 06｜排版与可读性清单（Markdown 友好）

> 目标：让读者在手机上也能“一眼看懂结构”，并愿意继续读。

## 1. 标题层级（最常用且不乱）

- `#`：文章标题（只出现一次）
- `##`：一级模块（导语/解析/实操/误区/结语）
- `###`：二级模块（细分段落）

建议：标题里尽量出现“可检索关键词”，比如“廓形 / 垂坠 / 比例 / 剪裁 / 语境”。

## 2. 段落长度（移动端友好）

- 每段 2–6 句为宜
- 遇到解释性强的段落：拆成 2 段，并用一句话小结

> 经验：读者不是讨厌长文，读者讨厌“没有呼吸的长文”。

## 3. 视觉节奏：让页面有“呼吸感”

### 3.1 加速阅读的元素

- 列表（`-` 或 `1.`）
- 对照表（Markdown table）
- 引用块（`>`）
- TL;DR（3 条总结）

### 3.2 强制小结（每个大段末尾）

```md
**小结：** {一句话结论}
```

## 4. 强调的分寸（避免“满屏加粗”）

- 一段最多加粗 1–2 处
- 只加粗“变量”和“结论”，不要加粗形容词

例：

```md
关键变量是 **垂坠感**，不是“好不好看”。
```

## 5. 图文配合规范（图片不是装饰，是证据）

### 5.1 推荐格式（图片 + 说明）

```md
![{简短alt}](图片链接或本地路径)
*图：{图片说明。指出你要读者看的变量}*
```

### 5.2 图片说明写法（模板）

- “看图时只盯一个变量：`{变量}`。”
- “左图 `{A}`：`{解释}`；右图 `{B}`：`{解释}`。”
- “结论：`{一句话}`。”

## 6. 引用与脚注（提高可信度）

### 6.1 引用块（适合短句）

```md
> “{引用句}”
> —— {作者/来源}
```

### 6.2 脚注（适合学术/长文）

```md
这与“{概念}”有关。[^1]

[^1]: {来源链接}（访问日期：{YYYY-MM-DD}）
```

## 7. Markdown 文章模板（开箱即用）

```md
# {标题}

> {一句话副标题/导语}

## 导语
{2 段以内}

## 深度解析
### {子标题}
{观点 → 证据 → 机制 → 迁移}

## 穿搭实操 / 方法
- {规则1}
- {规则2}

## 穿搭误区 / 反例
- {误区1}

## 结语
{一句话强收束}
```

## 8. 发布前自检（30 秒）

- [ ] 读者能在 10 秒内扫到你的结构（标题是否清晰）
- [ ] 每个大段都有“一句话小结”
- [ ] 是否至少有 1 个对比/反例（增强可信度）
- [ ] 图是否有“变量说明”（不然只是好看）
